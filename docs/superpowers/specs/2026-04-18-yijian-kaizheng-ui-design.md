# 一键开整桌面客户端 UI 设计文档

- 日期：2026-04-18
- 状态：设计已确认，待进入实现计划
- 范围：`desktop-client` UI 重构、品牌命名与文案系统、Remotion 动态图标、Stitch 界面方案
- 关联项目：`desktop-client`、`desktop-client/ui/*`

## 背景

当前桌面客户端已经具备账户、启动、计费与帮助模块，但整体仍属于“亮色平铺式后台界面”：

- 登录、注册、验证码、找回密码同屏堆叠
- 账户、启动、计费信息在主界面大面积平铺
- 品牌露出弱，进入感不足
- 缺少稳定的产品命名与可复用的文案人格
- 页面之间缺少“一级摘要 -> 二级详情 -> 三级结果态”的下钻层级

这次改造的目标不是单纯换皮，而是把客户端升级成一个有明确品牌感、进入感和层级感的桌面产品。

## 目标

- 将正式产品名从 `Sub2API Desktop` 升级为中文品牌名 `一键开整`
- 将现有平铺式信息结构改造成下钻式信息架构
- 将登录页改造成“老用户优先”的高级桌面产品入口
- 通过 Remotion 建立轻量但有记忆点的动态图标与过渡态
- 通过 Stitch 先产出关键页面设计，再回建到现有 Slint UI
- 建立“正式产品文案 + 电子牛马人格文案”双层文案系统
- 保持核心业务信息仍然专业、清晰、可信

## 非目标

- 本轮不调整后端接口契约
- 不新增支付流程或内嵌收银台
- 不将“梗文案”用于按钮、金额、安全说明或协议类页面
- 不把动态图标扩散到所有业务细节里
- 不把客户端做成宣传页风格或情绪化过强的娱乐产品

## 已确认的设计决策

以下约束已在设计讨论中确认：

- 正式产品名：`一键开整`
- 品牌气质：高级桌面产品，偏速度感与科技感
- 信息架构：所有主页面必须支持下钻，不允许继续平铺
- 登录优先级：老用户登录优先
- 登录页文案：
  - 标题：`欢迎王者归来`
  - 主按钮：`登录`
  - 补充选项：`记住密码`、`免登录`
- 动效策略：用于品牌入口、加载反馈、成功落定，不做大面积炫技
- 文案策略：
  - 正式层负责标题、按钮、状态、提示
  - 人格层由“电子牛马”承担，放在状态位和空态
- 梗感强度：半正式，允许带一点梗，但不影响支付、登录、安全等正式流程

## 品牌系统

### 正式产品名

- 主名：`一键开整`

命名意图：

- 直接命中“少折腾、一键启动”的核心价值
- 比单纯的“稳定”“代理”“桥接”更贴近用户行为
- 带一点轻梗，但仍能放在登录页、设置页、支付页等正式场景

### 启动口号

启动口号不固定为单句文案，而是按状态轮换，避免重复疲劳。

推荐口号池方向：

- `一键开整，启动！`
- `少折腾，直接开工。`
- `你的电子牛马已就位。`
- `准备就绪，直接开整。`

使用位置：

- 启动画面
- 登录成功过渡态
- 首次进入一级总览前的短时状态层

### 人格系统

客户端的人格名为：`电子牛马`

人格定位：

- 不是正式产品名
- 是负责承接状态文案与情绪价值的系统角色
- 帮助用户把“代理启动、兑换续费、失败重试、环境回收”理解成更轻松的交互体验

## 文案系统

### 正式层文案

正式层只负责产品主叙事与关键操作。

适用范围：

- 页面标题
- 按钮
- 表单标签
- 关键状态
- 金额与订阅信息
- 错误详情
- 安全说明

示例：

- `欢迎王者归来`
- `登录`
- `创建账户`
- `记住密码`
- `免登录`
- `正在验证身份`
- `连接已恢复`
- `兑换已到账`

### 人格层文案

人格层文案由“电子牛马”负责，只出现在次级状态位。

适用范围：

- 启动中
- 加载中
- 欠费提醒
- CDK 兑换成功
- 重试中
- 收工与环境回收完成

示例方向：

- `你的电子牛马已就位。`
- `电子牛马正在赶路。`
- `给你的电子牛马喂点草料。`
- `电子牛马获得了一次投喂。`
- `电子牛马刚刚打了个盹，正在重新探路。`
- `电子牛马已安全收工，原环境保持干净。`

### 使用边界

- 每个状态只出现一条人格文案
- 人格文案不与主操作抢注意力
- 人格文案不替代正式错误信息
- 欠费、失败、成功、回收等状态优先使用人格文案
- 登录、支付、安全、权限、协议等内容必须保持正式

## 视觉语言

### 整体方向

视觉方向为“高级桌面产品 + 速度与能量”：

- 不是纯后台系统，也不是营销宣传页
- 重点强化进入感、推进感、层级感
- 通过深色品牌区与浅色工作区建立对比
- 保持高级、克制、可信的气质

### 视觉特征

- 品牌区具备“能量核 + 轨道 + 推进线”的识别元素
- 工作区仍然偏浅色，以保证输入和阅读效率
- 主按钮需要更有推进感和行动号召力
- 卡片层级由“摘要卡 -> 详情卡 -> 结果态层”组成

### 禁止项

- 禁止继续使用“大量相似卡片平铺”的主布局
- 禁止在软件界面中出现解释设计意图的文案
- 禁止把品牌区做成静态 logo 加两行普通介绍

## 信息架构

本次改造统一改为三层结构：

1. 一级：摘要页
2. 二级：详情页或详情面板
3. 三级：动作结果态

所有模块都遵守这一规则，不再在一级页面把所有信息摊开。

### 一级：摘要页

一级只做三件事：

- 展示当前模块最核心的状态
- 提供一个明确的主动作
- 指向继续下钻的入口

### 二级：详情页

二级用于承接：

- 细节设置
- 补充信息
- 额外说明
- 次流程操作

### 三级：结果态

三级用于承接：

- 登录成功
- 兑换成功
- 启动成功
- 失败重试
- 环境回收完成

三级结果态需要统一视觉语言与文案节奏，避免每个模块各写一套。

## 页面结构设计

### 1. 启动画面

目标：

- 让用户在进入软件的第一秒感知到 `一键开整` 的品牌识别
- 建立“进入而不是填表”的产品第一印象

内容：

- 中文品牌名 `一键开整`
- Remotion 动态图标
- 一条轮换启动口号

### 2. 登录页

登录页是本轮最重要的视觉与交互入口。

确认后的首屏内容：

- 标题：`欢迎王者归来`
- 输入项：邮箱、密码
- 选项：`记住密码`、`免登录`
- 主按钮：`登录`
- 次入口：`创建账户`、`忘记密码`

结构：

- 左侧或顶部为品牌区
- 右侧或中心为登录主卡
- 初始状态只展示老用户主路径
- 注册与恢复不与登录主路径抢焦点

### 3. 登录页二级流

#### 3.1 2FA / 验证码展开态

- 默认不展示验证码输入框
- 只有服务端明确要求时才展开第二步
- 展开后保留同一张主卡，不跳出当前页面语言

#### 3.2 注册页

- 进入独立二级流
- 承接验证码发送、邮箱校验、密码创建
- 仍共享品牌区与整体视觉风格

#### 3.3 找回密码页

- 进入独立恢复流
- 使用正常产品语言说明步骤
- 成功后回到登录主路径或直接进入下一步

### 4. 一级总览页

登录成功后不再直接跳入平铺式仪表盘，而是先进入一级总览页。

总览页职责：

- 显示账户当前状态
- 给出下一步最重要动作
- 提供进入启动中心、计费中心、帮助与安全的下钻入口

总览页不直接展开订单、兑换记录、模式说明等大段内容。

### 5. 启动中心

#### 一级摘要

- 显示当前可用启动目标
- 显示官方模式与平台代理模式摘要
- 主动作是进入启动详情

#### 二级详情

- 展示目标安装状态
- 展示 `Desktop` / `CLI` 选择
- 展示 group 选择
- 展示本次启动的模式说明

#### 三级结果态

- 启动中
- 启动成功
- 启动失败
- 会话创建失败
- 环境恢复完成

### 6. 计费中心

#### 一级摘要

- 显示订阅摘要
- 显示一个主要动作，例如 `兑换 CDK`

#### 二级详情

- 订阅详情
- 订单详情
- 兑换记录
- 充值说明

#### 三级结果态

- 兑换成功
- 欠费提醒
- 订阅失效提醒

### 7. 帮助与安全

#### 一级摘要

- 显示恢复入口与安全原则摘要

#### 二级详情

- 安装诊断
- 模式限制
- 隐私与隔离边界

#### 三级结果态

- 恢复清理完成
- 检测失败
- 诊断建议生成完成

## 登录态与记忆选项规则

### 记住密码

- 用于本地安全存储用户登录凭据或可恢复登录材料
- 不要求用户再次手填基础信息
- 必须依赖系统安全存储

### 免登录

- 仅在当前设备有效
- 依赖本地安全凭据恢复
- 恢复失败时自动退回正常登录页
- 不应因为免登录而污染官方环境或平台代理环境

### 恢复流程

- 启动后检查免登录条件
- 有效时进入“身份恢复中”过渡态
- 凭据失效时回落登录页，并给出正式状态提示

## 页面流转

### 启动到登录

1. 展示品牌开屏
2. 检查免登录与本地凭据
3. 若恢复成功，进入过渡态
4. 若恢复失败或未开启免登录，进入登录页

### 登录成功

1. 用户点击 `登录`
2. 如需 2FA，则主卡扩展到第二步
3. 验证通过后进入短过渡态
4. 进入一级总览页

### 注册与恢复

1. 从登录页进入二级流
2. 完成对应流程
3. 返回登录页或直接进入下一步

### 一级总览到各模块

- 从一级总览进入启动中心、计费中心、帮助与安全
- 每个模块先摘要，再详情，再结果态
- 返回路径必须清晰，例如返回按钮、面包屑或阶段标签

## 错误态与成功态

### 错误态分层

错误态统一分为三层：

1. 字段错误
2. 动作失败
3. 系统异常

#### 字段错误

使用正式产品语言：

- `密码错误`
- `验证码已失效`
- `请输入有效邮箱`

#### 动作失败

需要同时满足两点：

- 给出真实错误含义
- 可以附带一条轻人格文案

例如：

- 正式信息：`启动失败，请检查安装状态`
- 人格补充：`电子牛马刚刚打了个盹，正在重新探路。`

#### 系统异常

- 需要清楚说明是否允许重试
- 需要给出是否能降级到官方模式
- 不使用模糊梗文案替代真实错误

### 成功态

成功态必须统一采用“短过渡 + 落定反馈”：

- 登录成功
- 兑换成功
- 启动成功
- 环境回收完成

成功态中允许出现一条人格文案，但要控制长度与频率。

## Remotion 落地方案

Remotion 负责品牌动态图标与关键过渡态动效。

### 动效范围

首批制作 4 组核心资产：

1. `待机核`
2. `登录推进`
3. `加载循环`
4. `成功落定`

### 动效语义

#### 1. Ignite

- 能量核点亮
- 用于开屏和等待进入前状态

#### 2. Thrust

- 推进线出现
- 表达“进入工作台”的动作感
- 用于登录成功和启动中的过渡

#### 3. Lock

- 动势收束成稳定形态
- 用于进入一级总览或启动完成

### 接入原则

- 优先作为轻量图标资产或短时动画资产接入
- 同时保留静态首帧作为降级方案
- 不在业务区做大面积持续动画
- 所有动效都必须短、准、收得住

## Stitch 落地方案

Stitch 负责先产出视觉稿和页面关系，再回建到现有 Slint。

### 首批输出页面

- 启动画面
- 登录页
- 2FA 展开态
- 注册页
- 找回密码页
- 一级总览页
- 启动中心摘要页
- 启动中心详情页
- 计费中心摘要页
- 计费中心详情页
- 帮助与安全摘要页
- 帮助与安全详情页

### 交付原则

- 先固定页面层级与视觉系统
- 再固定卡片规则、主次动作和状态层
- 最后映射到现有 `Slint` 组件结构

### 设计约束

- 所有页面都要体现下钻关系
- 不再做纯平铺仪表盘
- 主路径始终聚焦
- 品牌区和工作区各自承担明确职责

## 现有 Slint UI 改造重点

以下文件预期会成为主要改造对象：

- `desktop-client/ui/app-window.slint`
- `desktop-client/ui/screens/login.slint`
- `desktop-client/ui/screens/dashboard.slint`
- `desktop-client/ui/screens/launch_panel.slint`
- `desktop-client/ui/screens/redeem.slint`
- `desktop-client/ui/screens/forgot_password.slint`
- `desktop-client/ui/screens/about.slint`

改造方向：

- 重写登录页结构与状态层
- 重构主窗口信息架构
- 从“左侧导航 + 右侧平铺大卡”转向“一级摘要 + 二级详情”
- 增加统一的结果态与过渡态容器
- 引入产品名与统一状态文案体系

## 验收标准

### 视觉与品牌

- 软件主品牌名已替换为 `一键开整`
- 不再出现 `Sub2API Desktop` 作为正式产品名
- 不再出现设计提案式文案进入软件界面
- 登录页和开屏具备明确进入感与品牌识别

### 结构与交互

- 登录页主路径只聚焦老用户登录
- `记住密码` 与 `免登录` 已接入视觉与交互设计
- 所有主模块不再平铺全部内容
- 每个主模块都具备摘要、详情、结果态三级结构

### 动效

- Remotion 动效覆盖开屏、登录成功过渡、启动中、成功落定
- 动效接入后不影响主流程效率
- 存在静态降级方案

### 文案

- 正式层与人格层职责明确
- “电子牛马”文案只出现在允许场景
- 欠费、兑换成功、加载中、收工等状态存在轮换文案池

## 风险与注意事项

- 如果人格文案使用过多，会削弱高级感
- 如果动效停留时间过长，会影响工具产品效率感
- 如果 Stitch 设计稿只追求视觉而忽略层级，会回到“漂亮平铺”的老问题
- 如果在正式产品层继续混入提案文案，会损害品牌可信度

## 后续实现顺序建议

1. 用 Stitch 先出登录页、一级总览、启动中心和计费中心的高保真界面
2. 用 Remotion 产出 4 组核心动态图标资产
3. 在 Slint 中重构 `app-window` 与登录页主路径
4. 建立统一状态层与文案轮换策略
5. 再分模块推进启动中心、计费中心、帮助与安全的下钻结构
