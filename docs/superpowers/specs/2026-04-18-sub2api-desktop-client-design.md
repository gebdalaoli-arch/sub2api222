# Sub2API 桌面客户端设计文档

- 日期：2026-04-18
- 状态：设计已确认；后端桌面会话 Task 1/2 已实现；本节补齐 V1 错误处理、降级策略、范围边界和验收标准
- 范围：V1 桌面客户端 + `sub2api` 最小增量服务端改造

## 背景

目标是为 `sub2api` 构建一个面向终端用户的独立跨平台桌面客户端。客户端不展示 API Key、Base URL 或其他原始连接信息，而是直接启动本机已安装的 `Codex Desktop` 和 `Codex CLI`，支持两种模式：

- `官方模式`：启动用户原本已经配置好的官方 Codex 环境
- `平台模式`：通过受管桌面会话将 Codex 接到用户自己的 `sub2api` 服务

这套设计必须同时满足以下要求：

- 官方环境与平台代理环境完全隔离
- 首版实现和后期维护成本可控
- 不破坏 `sub2api` 现有网页端和现有 API 行为

## 目标

- 提供一个面向终端用户的全定制跨平台桌面客户端
- 首发优先保证 `Windows` 和 `macOS`
- 首版同时支持 `Codex Desktop` 和 `Codex CLI`
- 保证 `官方模式` 与 `平台模式` 完全隔离
- 在 UI 中隐藏 API Key、Base URL 与原始网关凭据
- 复用 `sub2api` 现有的登录、注册、余额、用量、CDK、公告等能力
- 仅对 `sub2api` 增加最小必要的桌面会话能力
- 启动切换保持为“会话级切换”，不改用户系统级默认状态

## 非目标

- V1 不做客户端内支付或内嵌收银台
- V1 不做 `Codex Desktop` / `Codex CLI` 自动下载与安装
- 不管理官方账号的登录、登出、多账号切换
- V1 不支持多站点或多后端切换
- 不在桌面客户端中展示、复制或管理 API Key
- 不重写现有网页端流程，也不改变现有 API Key 用户的接入方式

## 已确认的产品决策

以下约束已经在设计讨论中确认：

- 形态：跨平台桌面客户端
- 受众：终端用户
- 连接方式：固定连接单一 `sub2api` 站点
- UI 方案：全定制客户端界面，不使用 WebView 壳
- 信息架构：以仪表盘为主的首页结构
- 认证范围：登录、注册、忘记密码、邮箱验证码
- 账户页面：余额、用量、CDK 兑换、充值说明页
- API Key 管理：从 V1 界面中完全移除
- 启动对象：`Codex Desktop` 与 `Codex CLI`
- 切换方式：仅支持会话级切换
- 官方模式：只负责启动本机已登录的官方 Codex，不管理官方账号状态
- 安装前提：V1 依赖用户本机已安装 Codex 产品
- 数据隔离：官方历史与平台代理历史必须完全隔离
- 服务端改造：允许小改，但必须是增量式，不能破坏现有网页端和现有 API 行为

## 推荐技术方向

### 客户端运行时

推荐的 V1 技术栈：

- `Rust`
- `Slint`

推荐理由：

- 这个项目的核心难点是本机进程拉起、临时注入、Profile 隔离、异常恢复，天然更偏桌面控制器而不是网页壳客户端
- `Rust` 更适合处理子进程管理、文件系统隔离、临时目录生命周期和恢复清理这类强本机能力
- `Slint` 更贴近原生桌面 UI 方向，适合做长期的桌面产品形态，而不是把网页界面塞进一个桌面壳
- 首版虽然开发速度可能慢于 Web 技术栈，但长期看更符合“强接管桌面客户端”的目标

附加约束：

- 商业发布前需要明确 `Slint` 的许可使用方式，确认是否接受免费许可下的署名要求，或者是否需要商业许可

这是一条推荐技术路线，也是当前已确认的实现方向。如果后续因为授权、团队能力或交付节奏原因需要回退到其他桌面运行时，应单独修订本设计文档。

## 系统架构

V1 建议拆成 7 个客户端模块，加上 1 个服务端增量能力切片。

### 1. 账户中心

职责：

- 登录
- 注册
- 忘记密码
- 邮箱验证码
- 用户信息摘要
- 余额展示
- 用量展示
- CDK 兑换
- 充值说明内容展示

主要依赖现有服务端接口：

- `/api/v1/auth/*`
- `/api/v1/auth/me`
- `/api/v1/user/*`
- `/api/v1/usage/*`
- `/api/v1/redeem/*`
- 公告与订阅摘要相关接口

### 2. 本机探测

职责：

- 探测本机是否安装 `Codex Desktop`
- 探测本机是否安装 `Codex CLI`
- 识别可执行文件路径
- 确认目标是否可启动
- 将探测结果反馈给界面

### 3. 模式切换器

职责：

- 记录用户当前偏好的默认启动模式：`官方模式` 或 `平台模式`
- 仅对从本客户端发起的启动生效
- 不改系统全局默认状态

### 4. Profile 管理器

职责：

- 维护平台代理模式下的受管持久 Profile
- 分别维护 `platform-desktop` 与 `platform-cli`
- 保留平台代理历史与状态
- 永远不修改用户原本的官方 Profile

### 5. 启动编排器

职责：

- 为每次启动准备临时注入材料
- 启动 `Codex Desktop` 和 `Codex CLI`
- 处理桌面会话续期
- 监听子进程退出
- 触发清理与恢复逻辑

### 6. 安全存储适配层

职责：

- 将桌面客户端自己的登录态与敏感信息存放到系统安全存储中
- 避免把长期可用的网关凭据写入受管 Profile
- 避免敏感值进入日志、剪贴板或普通 UI 展示流程

### 7. 服务端适配层

职责：

- 调用现有 `sub2api` 账户相关接口
- 调用新增的桌面会话接口
- 将服务端返回状态统一整理为桌面客户端可消费的数据

### 8. 服务端桌面会话切片

职责：

- 为已登录用户签发桌面运行会话
- 校验桌面启动使用的短期凭据
- 处理桌面会话刷新与撤销
- 让桌面凭据与普通 API Key 在语义上彻底分离

## 服务端增量设计

服务端改造必须是增量式的，不影响现有网页端，也不影响现有 API Key 用户。

### 新增路由命名空间

建议新增一个独立路由组：

- `/api/v1/desktop/*`

这样既贴合 `sub2api` 现有路由风格，又能让桌面客户端专属能力和现有认证、Key 管理接口清晰隔离。

### 新增接口

#### `POST /api/v1/desktop/sessions`

用途：

- 为当前已认证用户创建一个可用于桌面启动的运行会话

请求字段：

- `target`：`desktop` 或 `cli`
- `group_id`：用户选择的可用分组，服务端负责校验分组权限或有效订阅
- `device_id`
- `device_name`
- `client_version`

返回字段：

- `session_id`
- `expires_at`
- `gateway_base_url`
- `runtime_token`
- `refresh_after`
- `profile_key`

说明：

- `runtime_token` 不是普通 API Key
- `profile_key` 用于让客户端把本次启动绑定到正确的受管 Profile 家族，而不暴露内部凭据语义

#### `POST /api/v1/desktop/sessions/:id/refresh`

用途：

- 在桌面会话仍然活跃时，为其续期

行为：

- 返回新的过期时间
- 如有需要，可返回轮换后的 `runtime_token`

#### `DELETE /api/v1/desktop/sessions/:id`

用途：

- 在正常退出时主动关闭桌面会话

行为要求：

- 幂等
- 可重复调用
- 如果客户端异常退出，仍由服务端过期策略兜底

### 新增桌面兼容网关入口

建议新增一条专供桌面模式流量使用的兼容入口，例如：

- `/api/desktop/v1`

这条路径只校验 `runtime_token`，而不是普通用户 API Key。服务端内部再将其映射回当前桌面会话、用户、计费和策略上下文。

这样可以同时保证：

- 桌面运行凭据不能被当作普通 API Key 使用
- 现有 API 使用方的行为不受影响

### 建议新增的数据模型

建议新增一个桌面会话数据模型，至少包含：

- `id`
- `user_id`
- `group_id`
- `device_id`
- `target`
- `status`
- `runtime_token_hash`
- `expires_at`
- `last_seen_at`
- `created_at`
- `revoked_at`

建议但非强制字段：

- `client_version`
- `device_name`
- `profile_key`
- `last_ip`

## 凭据时效策略

桌面运行凭据必须是“短期的，但不能脆弱”。

建议策略：

- `runtime_token` 默认有效期：`12 小时`
- 自动检查续期：每 `30 分钟` 一次
- 提前续期阈值：剩余时间少于 `2 小时`
- 续期失败缓冲期：`15-30 分钟`
- 正常退出时主动撤销会话
- 长时间失联或异常退出时由服务端自然过期

这样可以兼顾两件事：

- 不让凭据长期裸露在本机
- 不让用户因为时效过短而在正常长会话中频繁掉线

## 本地数据模型与 Profile 隔离

客户端本地分成 3 层存储。

### 1. App State

客户端自有的持久状态：

- 当前登录用户摘要
- 默认模式偏好
- 已探测到的安装路径
- 设备标识
- 最近一次启动记录
- 异常退出恢复标记

### 2. Managed Profiles

平台代理模式下的持久工作状态：

- `platform-desktop`
- `platform-cli`

这些目录用来保存平台代理模式的历史和本地状态，但不能保存长期可用的原始网关凭据。

### 3. Runtime Sessions

每次启动的临时运行状态：

- `session_id`
- 临时运行凭据
- 本次启动的连接覆盖配置
- 会话续期所需的记录信息

这些目录在正常退出时清理；如果上次异常退出，则在下次启动时优先清理。

### 隔离规则

- 官方 Profile 永远不被客户端修改
- `platform-desktop` 与 `platform-cli` 各自隔离
- 官方历史与平台代理历史彻底隔离
- 临时启动凭据不能沉淀进长期受管 Profile

## 启动流程

### 官方模式

流程：

1. 客户端检测本机是否存在目标 Codex 程序
2. 直接使用用户现有官方环境启动目标程序
3. 不创建任何 `sub2api` 桌面会话
4. 不修改任何官方 Profile 文件

结果：

- 官方登录状态仍然完全由用户自己管理
- 官方历史继续保存在原本官方环境所在的位置

### `Codex Desktop` 的平台代理模式

流程：

1. 客户端确认用户已登录 `sub2api`
2. 调用 `POST /api/v1/desktop/sessions`
3. 服务端返回短期桌面会话
4. 客户端针对 `platform-desktop` 这套受管 Profile 注入本次启动所需的连接覆盖
5. 启动 `Codex Desktop`
6. 进程存活期间按策略自动续期
7. 退出时调用 `DELETE /api/v1/desktop/sessions/:id` 并清理运行时残留

### `Codex CLI` 的平台代理模式

流程：

1. 客户端确认用户已登录 `sub2api`
2. 调用 `POST /api/v1/desktop/sessions`
3. 服务端返回短期桌面会话
4. 客户端针对 `platform-cli` 这套受管 Profile 注入本次启动所需的连接覆盖
5. 启动 `Codex CLI`
6. 进程存活期间按策略自动续期
7. 退出时关闭桌面会话并清理运行时残留

### 下次启动时的恢复流程

如果上一次是客户端崩溃、系统异常或 Codex 进程被强杀：

1. 扫描未清理的运行时会话目录
2. 尝试撤销对应的服务端桌面会话
3. 删除残留的临时注入文件
4. 保留平台代理的长期历史

这样即使上次退出不干净，受到影响的也只是“上次会话的临时连接材料”，不会破坏平台代理历史，更不会污染官方环境。

## 错误处理

V1 的错误处理目标不是“把所有问题都自动修好”，而是保证用户知道当前卡在哪里、能走可用路径、不会污染官方环境或泄露凭据。所有错误都按 `可重试 / 需用户操作 / 需服务端修复 / 安全拦截` 四类落地。

### 错误分类矩阵

| 场景 | 触发条件 | 用户提示 | 客户端动作 | 是否允许降级 |
| --- | --- | --- | --- | --- |
| 未登录或登录态失效 | `/auth/me` 或桌面会话接口返回 401 | “登录已过期，请重新登录” | 清除本地访问态，保留设备 ID 与非敏感偏好 | 是，可启动官方模式 |
| 邮箱验证码失败 | 验证码错误、过期、发送频率限制 | “验证码无效或已过期，请重新获取” | 不清空表单；保留冷却倒计时 | 不涉及启动降级 |
| 服务端不可用 | 网络超时、DNS 失败、5xx | “平台连接暂时不可用” | 后台指数退避重试；账户区显示离线状态 | 是，可启动官方模式 |
| 分组不可用 | `group_id` 缺失、无权限、订阅不存在或过期 | “当前套餐或分组不可用于平台模式” | 阻止平台模式启动；引导用户查看账户/公告 | 是，可启动官方模式 |
| 桌面会话创建失败 | `/desktop/sessions` 返回 4xx/5xx | “平台代理启动失败，本次未接管 Codex” | 不写入运行时注入文件，不启动平台代理模式 | 是，可启动官方模式 |
| Runtime Token 续期失败 | refresh 返回错误或网络失败 | “平台连接续期异常，正在重试” | 进入缓冲期，后台重试，不立即杀进程 | 过期前不降级；过期后要求重启 |
| Codex Desktop 未安装 | 探测不到可执行文件 | “未检测到 Codex Desktop” | Desktop 启动按钮禁用，显示安装说明 | 是，CLI 可继续 |
| Codex CLI 未安装 | `codex` 不在 PATH 或配置路径不可执行 | “未检测到 Codex CLI” | CLI 启动按钮禁用，显示路径设置入口 | 是，Desktop 可继续 |
| 子进程启动失败 | 进程创建失败、权限不足、路径失效 | “启动失败，请检查安装路径或权限” | 不标记为启动成功；撤销已创建的平台会话 | 是，可启动另一个目标/官方模式 |
| 异常退出或强杀 | 客户端崩溃、系统重启、Codex 被杀 | “检测到上次退出不完整，已清理临时连接材料” | 下次启动优先清理 runtime 目录并尝试 revoke | 是，保留受管历史 |
| 安全拦截 | token 缺失、group 上下文缺失、会话非 owner | “平台会话无效，请重新启动” | 删除本次 runtime 材料；要求重新创建会话 | 是，可启动官方模式 |

### 日志与敏感信息规则

- 日志可以记录 `session_id`、错误码、HTTP 状态码、目标类型、是否进入降级路径。
- 日志不能记录 `runtime_token`、普通 API Key、Authorization header、完整注入配置内容。
- UI 不展示普通 API Key、Base URL、runtime token、临时配置文件内容。
- 剪贴板、崩溃报告、调试导出都不能包含可直接使用的连接凭据。

### 重试规则

- 登录、注册、验证码：不自动重试，由用户主动操作，避免重复发送或账号锁定。
- 桌面会话创建：最多自动重试 1 次；仍失败则停止平台启动。
- 会话续期：进入 15-30 分钟缓冲期，按 `30s / 60s / 120s / 300s` 退避重试。
- 会话撤销：正常退出时最多重试 3 次；失败则写入恢复队列，下次启动继续清理。
- 本机探测：每次打开启动页重新探测；用户也可以手动刷新。

## 降级策略

降级策略按“保护官方环境优先、保留可用功能、明确阻断危险路径”执行。

### 降级优先级

1. `官方模式` 是最高优先级保底路径。平台服务异常时，仍允许用户启动本机官方 Codex。
2. `Codex Desktop` 与 `Codex CLI` 相互独立。一个目标不可用，不影响另一个目标的探测和启动。
3. `账户功能` 与 `启动功能` 相互独立。平台启动失败时，仍允许查看公告、余额、用量、CDK、充值说明。
4. `受管 Profile` 与 `Runtime Session` 相互独立。清理临时会话不得删除平台代理历史。
5. `安全拦截` 高于可用性。只要 group/session/token 上下文不完整，就不能继续平台代理模式。

### 降级后的 UI 状态

- 顶部状态条显示当前模式：`官方模式可用`、`平台代理可用`、`平台代理不可用`、`离线`。
- 启动按钮必须说明禁用原因，例如“未安装 CLI”“套餐已过期”“平台服务不可用”。
- 降级到官方模式时，不提示用户复制任何 API 信息。
- 平台模式不可用时，不能自动改写用户系统级 Codex 配置。

### 不允许的降级

- 不允许把普通 API Key 暴露给用户作为“手动兜底”。
- 不允许把 runtime token 当作普通 API Key 持久保存。
- 不允许在平台失败后修改官方 Profile 再尝试恢复。
- 不允许在无法确认 owner/group/subscription 上下文时继续计费流量。

## V1 范围边界

### V1 必须包含

- 固定单一 `sub2api` 后端，不提供多站点切换。
- 登录、注册、忘记密码、邮箱验证码。
- 余额摘要、用量摘要、CDK 兑换、充值说明公告页。
- 本机 `Codex Desktop` 与 `Codex CLI` 探测。
- 官方模式启动：不创建平台会话，不修改官方环境。
- 平台模式启动：创建桌面会话，按 `group_id` 绑定分组/订阅上下文。
- `platform-desktop` 与 `platform-cli` 两套受管 Profile。
- 每次平台启动生成独立 runtime 目录、临时配置和临时环境变量。
- 正常退出撤销会话，异常退出下次启动恢复清理。
- 不展示 API Key、Base URL、runtime token 或任何可复制网关凭据。

### V1 可以延后但架构需兼容

- 客户端内支付和支付回调展示。
- 设备管理、远程解绑、会话列表。
- Codex 自动下载与安装。
- 多后端白牌切换。
- 更细的套餐升级推荐与营销页面。
- 托盘常驻、后台自动拉起、开机启动。

### V1 明确不做

- 不管理官方账号登录状态。
- 不代理或同步官方历史。
- 不提供系统级全局模式切换。
- 不在客户端内创建、查看、复制普通 API Key。
- 不做本地常驻桥接代理。
- 不绕过服务端分组、订阅、计费、路由策略。

## 验收标准

V1 验收以“能安全启动、能明确失败、能降级、能恢复”为主，不以页面数量作为唯一标准。

### 服务端验收

- `POST /api/v1/desktop/sessions` 必须要求登录态和 `group_id`。
- 普通分组必须校验用户绑定权限；订阅分组必须校验有效订阅。
- `POST /api/v1/desktop/sessions/:id/refresh` 和 `DELETE /api/v1/desktop/sessions/:id` 必须绑定 owner，不能跨用户刷新或撤销。
- `/api/desktop/v1/*` 必须只接受 runtime token，不接受普通 API Key 替代桌面会话。
- runtime auth 必须向后续网关注入 user、group、api key 语义对象和 subscription 上下文。
- 缺失 group 上下文、过期会话、撤销会话、未知 token 都必须拒绝。
- 数据迁移必须兼容已跑过旧迁移的环境：新增字段走新迁移，不直接修改已发布迁移。

### 客户端功能验收

- 用户可完成注册、登录、忘记密码、邮箱验证码流程。
- 用户可查看余额、用量、公告式充值说明，并可兑换 CDK。
- 客户端能识别 Desktop/CLI 的安装状态，并分别展示可用、不可用和刷新状态。
- 官方模式能启动本机已安装目标，且不会创建平台会话。
- 平台模式能为 Desktop/CLI 创建会话、准备受管 Profile、启动进程并定期续期。
- 正常退出后能撤销平台会话并清理 runtime 目录。
- 异常退出后，下次启动能清理残留 runtime 材料并保留平台代理历史。
- 所有 UI 都不出现 API Key、Base URL、runtime token 或可复制网关凭据。

### 隔离验收

- 官方模式启动前后，官方 Profile 文件不被客户端写入。
- 平台模式只写入客户端受管目录和本次 runtime 目录。
- `platform-desktop` 与 `platform-cli` 的历史和状态互不覆盖。
- 删除 runtime session 不会删除受管 Profile 历史。

### 降级验收

- 服务端不可用时，官方模式仍能启动。
- Desktop 未安装时，CLI 入口仍可用；CLI 未安装时，Desktop 入口仍可用。
- 平台会话创建失败时，不留下可用 token 或半写入配置。
- 续期失败但 token 未过期时，不立即杀掉用户进程；真正过期后提示重新启动平台代理模式。
- 撤销失败时写入恢复队列，下次启动继续清理。

### 人工验收脚本

首版发布前至少执行以下人工路径：

1. Windows：登录 -> 兑换 CDK -> 官方模式启动 Desktop -> 退出。
2. Windows：登录 -> 平台模式启动 CLI -> 续期一次 -> 退出并确认 runtime 清理。
3. macOS：登录 -> 平台模式启动 Desktop -> 强杀客户端 -> 下次启动执行恢复清理。
4. 断网：进入客户端 -> 账户区显示离线 -> 官方模式仍可启动。
5. 订阅失效：平台模式被阻止 -> UI 不展示任何 API 信息 -> 官方模式仍可用。

## 后续实现阶段的测试策略

实现计划至少要覆盖以下测试层级：

- `/api/v1/desktop/*` 的服务端契约测试
- 桌面兼容网关中 `runtime_token` 校验测试
- 客户端本机探测与启动编排的集成测试
- 运行时残留清理与恢复测试
- `Windows` 与 `macOS` 的人工启动验证
